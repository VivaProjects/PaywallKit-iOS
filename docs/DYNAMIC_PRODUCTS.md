# 动态页面商品

`PaywallCatalog(productRefs: initialIDs, recommendedRef: initialID, allowsDocumentProducts: true)`

新增参数默认 false，旧宿主继续使用固定白名单。显式开启后，经过来源、环境、包身份与资源校验的页面清单可以包含初始目录之外的非空商品 ID。远端页面、缓存恢复、历史回退和内置包使用一致的策略。不得将本地商品缓存当作页面购买授权。

宿主的 `PaywallPurchaseBridge.products` 应连接单一商品仓库：按页面请求集合复用内存商品，批量补查缺失商品，合并在途请求，只登记商店实际返回且属于支持类型的 ID。持久化环境隔离的 ID，不持久化价格或优惠；下次启动重新查询商店。请求失败或空商品允许重试，消费者取消不应取消其他消费者共用的任务，商店变化须清理旧内存结果。

宿主购买桥必须再次校验 ID 属于当前会话页面及购买许可，随后使用真实商店商品购买、验单和确认权益。H5 不能直接新增商品权限。SDK 不自行保存另一份商店产品表，也不直接操作宿主 UserDefaults。

本次未改桥消息、H5 注入字段或页面包格式。Flutter/浏览器预览协议无需迁移，但动态目录为 iOS 的新增 opt-in 能力，不能据此认为 Flutter 已支持动态商品。后台仍应按旧宿主版本区分发布。

本次静态验证不代表商店查询、缓存生命周期、真实购买或恢复已通过设备验收。未发布 SDK 版本。
